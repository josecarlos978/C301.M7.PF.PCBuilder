# 📘 Guía de Pruebas Funcionales – CRM + Configurador de PCs

## 1. Objetivo

Validar que el sistema respete las **reglas de compatibilidad técnica** definidas en la especificación y que el flujo en cascada del configurador funcione correctamente desde CPU hasta PSU.

## 2. Casos de Prueba Principales

### 🖥️ CPU

- **Caso 1:** Seleccionar CPU AMD AM5 → el sistema debe mostrar solo placas madre con socket AM5.
    
- **Caso 2:** Seleccionar CPU Intel LGA1700 → el sistema debe mostrar solo placas madre con socket LGA1700.
    
- **Caso 3:** CPU con `requiereCooler = true` → el sistema debe obligar a seleccionar un cooler compatible.
    
- **Caso 4:** CPU con `tieneGraficosIntegrados = false` → el sistema debe obligar a seleccionar una GPU dedicada.
    

### 🖧 Placa Madre

- **Caso 5:** Placa madre DDR5 → el sistema debe mostrar solo RAM DDR5.
    
- **Caso 6:** Placa madre con 2 slots → el sistema debe bloquear selección de más de 2 módulos de RAM.
    

### 💾 RAM

- **Caso 7:** Seleccionar RAM DDR4 con placa DDR5 → el sistema debe bloquear la configuración.
    
- **Caso 8:** Seleccionar RAM con frecuencia incompatible → el sistema debe advertir pero permitir si la placa soporta frecuencia inferior.
    

### 🎮 GPU

- **Caso 9:** Seleccionar GPU de 300mm → el sistema debe mostrar solo cases con `largoMaxGpuMm >= 300`.
    
- **Caso 10:** GPU con consumo recomendado 650W → el sistema debe obligar a PSU ≥ 650W (o case con fuente ≥ 650W).
    

### ❄️ Cooler

- **Caso 11:** CPU con TDP 120W → el sistema debe mostrar solo coolers con `tdpSoportadoWatts >= 120`.
    
- **Caso 12:** Cooler con socket incompatible → el sistema debe bloquear la selección.
    

### 🏠 Case

- **Caso 13:** Placa ATX → el sistema debe mostrar solo cases que soporten ATX.
    
- **Caso 14:** Cooler con 3 ventiladores → el sistema debe mostrar solo cases con `soportaFanCoolerVentiladores >= 3`.
    

### 🔌 PSU

- **Caso 15:** Case con fuente incluida de 250W → el sistema debe bloquear GPU que requiera ≥ 300W.
    
- **Caso 16:** Case sin fuente → el sistema debe obligar a seleccionar PSU.
    
- **Caso 17:** PSU modular vs no modular → el sistema debe registrar correctamente el atributo pero no bloquear compatibilidad.
    

## 3. Validaciones de Cotización

- **Caso 18:** Generar cotización con CPU + Placa + RAM compatibles → debe calcular precio total y permitir exportar PDF.
    
- **Caso 19:** Generar cotización con GPU incompatible → debe bloquear y mostrar mensaje de error.
    
- **Caso 20:** Cotización enviada por WhatsApp → debe registrar borrador en ERP.
    

## 4. Pruebas de Integración

- **Caso 21:** Panel administrativo debe permitir modificar atributos de producto y reflejar cambios en el configurador.
    
- **Caso 22:** CRM debe listar cotizaciones por cliente y permitir cambiar estado (Borrador → Confirmada).
    
- **Caso 23:** Reporte de ventas debe sumar correctamente cotizaciones confirmadas.
    

## 5. Resultado Esperado

- Todas las reglas de compatibilidad deben ser **bloqueantes**.
    
- El flujo en cascada debe guiar al usuario sin permitir configuraciones inválidas.
    
- Cotizaciones deben generarse con precios correctos y exportarse en PDF o enviarse por WhatsApp/Correo.
    
- El panel administrativo debe reflejar inventario y cotizaciones en tiempo real.
